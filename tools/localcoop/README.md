# Local co-op test tools (developer only, not shipped)

- `launch.ps1`: kills PBZ, starts one copy with the mod, presses through the title menu until a player pawn exists.
- `run.ps1 -Cmd '<mod command>'[, ...] [-Wait s] [-Shot path.png]`: sends commands through cmd.txt and prints the mod's new log lines; `-Shot` captures the game window.
- `test-helpers.lua`: load in game with `run.ps1 -Cmd 'eval return dofile("<full path>/test-helpers.lua")'`. Gives `T.go/T.land` (streaming-safe teleport: fly, wait ~3 s, land), `T.move/T.press/T.hold` (held input injection per player), `T.climb/T.interact/T.enemies/T.items/T.widgets`, `T.pair/T.lookAt/T.nearEnemy`, and the enemy AI probes: `T.enemyList` (hatred lists), `T.aiState` (state tag), `T.domains` (fight areas and who is inside), `T.calmFar`/`T.frontOf` (pick a calm far enemy and stand player 2 before it), and `T.walkTo/T.walkPair/T.stopWalk` (steer a player, or both, to a point with held move input; the story triggers want a real walk, not a teleport).
- `soak.ps1 -Minutes N`: unattended wander/sprint/attack soak for both players, logs state and Lua errors.
- `vpad.py`: two virtual X360 pads on the ViGEm bus (close DS4Windows first; commands in vpad_cmd.txt: "<pad> <lx> <ly> <rx> <ry> <buttons> <seconds>", A=4096, Start=16, dpad right=8).

Rules learned the hard way: never teleport enemies from Lua (crash); check an actor's location is sane before teleporting a player to it; a far teleport needs the fly-wait-land sequence or the player falls through unloaded ground.

What crashed the game from Lua (2026-11-01, three times): reading every property of a blueprint object in a loop, iterating a TMap, and calling an enemy function (ForceIntoCombat) on an enemy that had just died. Read named bool/number/name properties and object arrays only, and check `valid` and health before calling into an enemy. Hooks (`RegisterHook`) on blueprint and native functions are safe for watching: the SGameAI sense callbacks, `AIPerceptionSystem:ReportPerceptionEvent`, the ASM component's key events.
- Story probes (2026-11-01), each run with `run.ps1 -Cmd 'eval <OUT>="<path>.txt" return dofile("<full path>/<probe>.lua")'` and read from the text file: `scout.lua` (`SCOUT_OUT`, optional `SCOUT_PATS`/`SCOUT_MAX`: level actors whose class or name matches, nearest first), `story.lua` (`STORY_OUT`: the Narrative quests, the flow components with executing nodes, every switch/door with its item requirement), `quest.lua` (`QUEST_OUT`: states and branches of the quests in progress; the branch's `point` is a MapTargetPointActor id whose location is where the story continues).

What was learned driving chapter 1 with two players: story triggers want a real walk (teleporting into a TriggerBox fires nothing); the Traverse map pans with the mouse cursor and could not be scripted (ESC twice leaves it); what blocks a player at a fog line is level collision (ignoring the BP_FogDoor_C actors, and even the 118 small PBZPlayableZoneVolume actors that line the paths, with IgnoreActorWhenMoving did not let player 2 through), so the mod joins player 2 to the fight by teleport instead; never give player 1 a Health_Min and then teleport it (a fall through unloaded ground never ends).

Added 2026-11-01 (afternoon pass):
- `key.ps1 -Keys ESC,RETURN,E [-Gap s] [-Shot path.png]`, `click.ps1 -X <x> -Y <y> [-Shot path.png]` (half-scale screenshot pixels): drive player 1's keyboard and mouse. Both bring the game to the front first and refuse to send anything unless the game window is really the foreground window, because a system prompt (a Windows Firewall question came up for another copy of the game mid-test) would otherwise take the RETURN or ESC. `log.ps1 -Minutes N [-Last M]` prints the mod's log with timestamps (`run.ps1` only shows lines written after its own start, so a tip that fired while PowerShell was starting is missing there). `continue.ps1` takes an already running copy from the title into the save.
- All of these look only at PBZ.exe processes whose Path is under D:\SteamLibrary, and `game-driver.ps1` filters on its -GameWin64 folder: a second copy of the game may be running from another folder for other tests, and nothing here may stop it.
- A pad drop is faked with `pads_fake.txt` in the mod folder (one digit per line, as pads.txt: 0 gone, 1 in, 2 a button held); delete it afterwards. 0000 → both players "disconnected" with a health floor, 1100 → "back", 0120 → pad 3 claims player 1 in a second, 2100 → pad 1 takes it back; localcoop.txt follows.
- Lua cannot kill a player: `pawn:Kill` is not callable and `applyDamage` only zeroes the health (the mod then revives player 1 by hand after 6 s). A real death needs an enemy hit (player 1 at 1 hp in the Peng Meng arena, approach by flying to -50305,259530,-24200 and landing) or a fall out of the world (also leaves a WB_PBZHelpManager_C page up until a key is pressed, and the game's respawn step then runs late, when that page closes).
- The bell's "Save" is the save-slot screen, not a rest; the bell menu ignores keyboard DOWN (click the entry). An unopened chest has `CurSwitchState == false`; the two left on Xigu are at -73425,254734,-20855 and -51155,208571,-20980 (the second one neither player targets).
- "Return to Title Screen" with player 2 still a local player gave a black title screen (no UI layouts at all); the mod now removes player 2 in a LoadMap pre-hook (`RegisterLoadMapPreHook`) and creates them again on the new map.
